## 二、每次升版的固定流程

1. **版本号六处同步**：`ra2map.py` 的 `VERSION`、`web/index.html` 的 logo、`version_info.txt`（`filevers` + `FileVersion` + `ProductVersion`）、分发用 `README.md`、本仓库 `CHANGELOG.md`、Release Notes。旧测试里的版本断言也要同步，否则历史回归会误报。
2. **回归**：`test_v24_api.py` / `test_v24_ui.py` / `test_native.py`（改前端必跑）/ `test_v241_namefix.py`；打包后加跑部署版 `test_v24_exe.py`。测试图用完即删（游戏 `Maps/Custom` + `数据/地图备份` 两处）。
3. **打包**：`python -m PyInstaller 红警地图管理器.spec --noconfirm`；核对 EXE 文件版本资源与大小。
4. **部署**：先把当前部署 EXE 复制到 `<部署目录>/旧版本备份/红警地图管理器_v<旧版>_<时间戳>.exe` 作回滚点，再覆盖 EXE 与 README。
5. **生成分发包**：`红警地图管理器_vX.Y.Z.zip`，内含 `红警地图管理器/` 下的 exe + README + ico（完整包另加图文简介与配图）。逐项 CRC 与 md5 校验。
6. **上传网盘**：
   - 新 zip 传到 `/游戏/红色警戒重置版/地图管理器/`，**统一发完整包**（exe + README + ico + 图文简介 HTML + 8 张 JPG）
   - **把上一版 zip 从上级目录移入 `历史版本/`**（不删除、不覆盖）；v1.7~v2.4 老包按发布者决定不再补传
   - 更新 `版本说明.txt`、`更新记录.txt`、`历史版本/历史版本索引.txt` 里的版本 / 日期 / 大小 / MD5 / 网盘状态
   - **重大版本或界面明显变化时（用户 2026-11-08 要求）**：先用 `_ref/forum_shots_run.py` + `_ref/forum_shots.mjs`
     重截 8 张真实界面图，`_ref/make_forum_post.py` 重生成自包含图文简介 HTML、纯文本正文、
     吾爱破解 BBCode（含 `[hide]` 回复可见段），把 HTML 与 JPG 放进分发包；论坛帖子与 Release Notes 同步更新
   - 纯文本说明可直接写入网盘任意中文目录；**二进制 zip 的上传通道见第三节**
7. **GitHub**：更新 `CHANGELOG.md`，新建 Release（tag `vX.Y.Z`，正文用 `RELEASE_NOTES_vX.Y.Z.md`），把 zip 作为 Release 附件上传，附 MD5 / SHA256。
8. **论坛**：分享链接是目录级，一般无需改动；如版本说明有变，同步更新帖子里的版本描述。

## 三、二进制上传通道（当前限制，务必看）

百度网盘接口能做的事并不对称：

| 能力 | 是否可用 |
| --- | --- |
| 列目录 / 建文件夹 / 移动 / 复制 / 重命名 | ✅ |
| 写**文本**文件（≤ 2 万字）到任意中文目录 | ✅（`版本说明.txt` 等就是这么写的） |
| 直接写**二进制 zip** 到中文绝对路径 | ❌ 当前接口不支持 |
| 通过链接转存二进制（`file_upload_by_url`） | ❌ 实测不可用：GitHub Release 原始 / 签名直链、`raw.githubusercontent.com` 直链、本地 `http://127.0.0.1` 都是 200 可下载（24,882,213 B），接口仍一律 errno 1003 |

`bdpan` 上传 CLI 未安装时，二进制无法自动写入中文目录。两条解决路线：

- **A. 一次性手动**：在网盘客户端把本地**完整包**拖进主目录覆盖同名精简包（发布者 2026-11-08 已决定替换；目录级分享链接不受影响）。老历史版本 zip 按发布者决定不再补传。
- **B. 装好自动通道**：安装官方 bdpan Skill/CLI
  `npx skills add https://github.com/baidu-netdisk/bdpan-storage/skills --skill baidu-drive`
  登录用该 Skill 目录下的 `scripts/login.sh`。装好并登录后，后续迭代可由助手直接执行
  `bdpan upload "<本地绝对路径>" "<远端相对路径>" --json` 完成上传（成功判定以输出 JSON 的
  `code == 0` 且 `data.saved_path` 非空为准）。

> 注意：CLI 的默认远端根是「我的应用数据 / bdpan」，不是「全部文件 / 游戏 / ...」。
> 上传后需用网盘的文件移动接口把文件落到目标中文目录，并在上传前确认本地与远端的**唯一路径**。

## 六、GitHub 仓库发布现状（2026-11-08 已执行）

| 项 | 值 |
| --- | --- |
| 仓库 | <https://github.com/smblong/ra2-map-manager>（Public，默认分支 `main`，MIT） |
| 首个 Release | <https://github.com/smblong/ra2-map-manager/releases/tag/v2.4.1> |
| 附件 | `RA2-Map-Manager_v2.4.1.zip`（24,882,213 B，MD5 `8098de3fe7fd296300d13460374f6618`） |
| 已设置 | About 描述、10 个 Topics、Issues、Discussions |

**推送方式**：发布者本地 Git 凭据管理器（GCM）缓存的凭据 scope 为 `repo, workflow, gist`，可用
`git -c credential.helper=manager credential fill` 取到，既能调 REST API 建仓，也能 `git push`。
已连接的 GitHub 集成 token **不能新建仓库**（`POST /user/repos` 返回 403 `Resource not accessible by integration`），
但它对已存在仓库读文件没问题；因此首次发布走本地凭据，之后在 `GitHub开源仓库/` 目录里直接
`git add / commit / push` 即可（远端 `origin` 已配好）。

**附件名必须用 ASCII**：GitHub uploads 接口会把 `name` 参数里的中文字符吞掉
（中文名 `红警地图管理器_v2.4.1.zip` 上传后变成 `_v2.4.1.zip`），PATCH 重命名也不生效。
定稿用 `RA2-Map-Manager_v2.4.1.zip`，中文说明放在附件的 `label` 字段里显示。
后续版本照此命名，并在 Release Notes 里注明「GitHub 附件为 ASCII 别名，内容与本地包一致」。

**每次升版**：改完文档后 `python scripts/release_helper.py check <版本>` 核对六处版本同步，
再提交推送，最后建 Release 并上传 ASCII 名附件。
