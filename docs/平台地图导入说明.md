# 平台地图导入说明

## 支持哪几类来源

`platform_import.py` 对平台目录做**只读扫描**，把能识别的条目汇总成一张可勾选清单：

| 来源 | 说明 | 能否导入 |
| --- | --- | --- |
| `RA2/Res/MP.dat` | 本质是 ZIP，内含明文标准 `.map` 与 `thumb_<hash>.jpg` 预览 | ✅ 主体 |
| `RA2/Map/*.ra2mp` | 平台自有打包格式（也是 ZIP），`1.txt` 加密主体 / `3.txt` GBK 元数据 / `5.txt` JPEG 预览 | ❌ 标为 `locked`，只展示元数据与预览 |
| `mp.dat` / `spawnmap.ini` | 平台开一局后落在**游戏目录**的解包缓存，是明文标准地图 | ✅ 加密图的正确通道 |
| 本地散图 / ZIP 地图包 | `.map/.mpr/.yrm/.mms` 或含这些文件的 ZIP | ✅ |

## 实测样本（HTPlatform 类平台）

- 平台目录：`<平台安装目录>`，`Config.ini` 里的 `fwht` 指向游戏主程序
- `MP.dat`：**171 张明文标准地图** + **173 张 `thumb_<hash>.jpg`**
- `RA2/INI/nmap.ini` / `nmap8.ini`：GBK 索引，按 40 位 hash 给出中文名、人数、模式，共 173 条
- 预览配对：`thumb_<hash>.jpg` 的 hash **前 16 位**与地图条目 hash 前缀匹配，实测 **171/171 命中**
- `RA2/Map/*.ra2mp`：2 个（V3 / V4 各一），元数据里能读到中文名、人数、Size、Theater、Waypoints
- 解包缓存：平台目录下的 `mp.dat` 实测是明文 `[SpecialFlags]...` 标准图，`spawn.ini` 里有 `UIMapName=[4] Caverns of Siberia`
- **合计 174 条 / 可导入 172 / 加密锁定 2**

## 为什么 `.ra2mp` 不导入

`.ra2mp` 是 ZIP，结构大致是：

```
1.txt   高熵，平台自有加密的地图主体
2.txt   [csf] num=0 ...
3.txt   GBK 元数据（Name / MaxPlayer / Ra2mpVer / Size / Theater ...）
4.txt   [Settings] ShortGame=True 或空
5.txt   JPEG 预览
6.txt / spawnmap.ini   空或辅助段
```

对 `1.txt` 试过简单/循环 XOR、字节 add/sub、bit reverse、nibble swap、RC4、OpenSSL 常见对称加密（AES / DES / RC2 / Blowfish / Camellia）、zlib raw deflate、用文件名 hash 作 key 等，都还原不出合法 INI 或压缩流；平台官方资料也说明该格式拥有算法著作权、地图主体「部分加密」，**无法从外部获取地图代码**。

因此本项目：

1. 只解析 `3.txt` 元数据与 `5.txt` 预览，让它在清单里可见、可看图
2. `ready=false`、`kind='locked'`，`import_items()` 对这类项**拒绝写入**
3. 提供可靠替代通道（见下）

> 宁可锁定，也不把一张进游戏就崩的坏图塞进 `Maps/Custom`。

## 加密图的正确导入方式

1. 在平台里打开该图 / 开一局
2. 平台会把解密后的明文地图落到游戏目录的 `mp.dat` / `spawnmap.ini`
3. 回到本工具「平台导入」→ 扫描「平台解包缓存」→ 勾选导入

## 导入规则

| 项 | 规则 |
| --- | --- |
| 平台目录 | **全程只读**，不修改平台任何文件 |
| 默认目标 | 当前游戏的 `Custom` 目录（可切其它地图目录） |
| 同名处理 | `skip`（默认）/ `rename` / `overwrite` |
| 覆盖前 | 自动备份到 `数据/地图备份/` |
| 写入校验 | `import_items()` 再做一次 `_is_map_text(data)`：非标准 INI 头、长度不足、JPEG/ZIP 伪装一律拒绝 |
| 测试 | 接口测试只写临时目录，不污染真实游戏目录 |

## 想适配新平台

在 `platform_import.py` 里加一个扫描分支，注意：

- 文本解码优先 GBK，回退 UTF-8 / latin-1
- 中文名尽量从平台索引还原，别用 hash 文件名当名字
- 预览配对规则要写清楚（hash 前缀？同名？索引字段？）
- 任何无法确认是**明文标准地图**的条目都要 `ready=false`，不要猜
- 附上平台目录结构说明与可公开的样本，**不要上传加密主体或平台资源**
